大家好，我是「山丘代码铺」。

8 月 28 日，腾讯混元发布了新一代旗舰模型 Hy4 preview。

发布页里最有意思的一段，是 Hy4 preview 自己担任研究员，同时指挥多个 Codex 会话并行做实验。

实验结果回来以后，Hy4 会判断哪条路更有效，再安排下一轮。按照腾讯公布的结果，这套方案在 8 项基准上全部超过了 Codex 单独探索。

以前聊代码模型，更多是在看它自己能写多少代码。Hy4 这次往前挪了一步，它开始管理其他编码 Agent 的工作。

再看模型规格，数字也不小。

770B 总参数，每个 token 激活 49B，1M 上下文。

模型权重已经按 Apache 2.0 许可证开放，API 同时上线腾讯云 TokenHub 和 OpenRouter，第二天又进了 OpenCode Go。

我把腾讯发布页、GitHub 部署说明和 OpenRouter 的早期数据对了一遍，目前还没有拿 Hy4 跑过完整代码项目。这篇先看官方材料能确认的变化，也把厂商自测和外部运行数据分开。

## 已经开始指挥多个 Codex 干活

腾讯给 Hy4 安排的是一项小模型后训练研究。

Hy4 负责制定研究方向，多个 Codex 会话并行执行实验。结果回来以后，Hy4 要评估哪组改动有效，再调整下一轮。按照腾讯公布的数据，Hy4 协调 Codex 的方案在 8 项基准上都超过了 Codex 单独探索。

这个案例来自腾讯自己的实验，外面暂时无法完整复现。它展示的产品方向却很清楚。Hy4 要写代码，也要拆分研究任务，子 Agent 交回来的结果还得由它继续判断。

这正好踩在现在 Agent 工程最难的一块。

调用几个子 Agent 很容易。子 Agent 返回一堆内容以后，主模型能不能判断哪条路有效，愿不愿意停掉错误实验，再把多轮结果收回同一个目标，才决定整个任务有没有做完。

腾讯的官方基准图还把 Hy4 放进了 12 项测试。对手包括 Qwen3.8-Max 和 DeepSeek-V4-Pro 0813，GPT-5.6 Sol、GLM-5.3、Kimi K3 与 Claude Opus 5 也在同一张图里。Hy4 在多项 Agent 和研究任务上进入了头部区间，也有项目仍然落后于其他模型。

这张表由腾讯组织评测，目前还缺少足够的独立复测。我更愿意把它当成模型定位，Hy4 已经朝长程 Agent 和复杂研究任务发力，具体名次还要等外面的团队重新跑。

腾讯还做了一组内部盲测。163 名内部专家评了 203 个工程任务，Hy4 preview 的平均分是 2.99，GLM-5.3 是 2.92。逐项比较时，Hy4 赢下 46.8%，打平 12.8%，输掉 40.4%。

和 Kimi K3 对比，平均分是 2.99 对 2.94。Hy4 的胜率为 51.2%，另有 7.9% 打平，剩下 40.9% 落后。

领先有，但没有拉开很大距离。

官方数据能说明 Hy4 已经进入开源旗舰的竞争区间，还不能替每个项目做选型。

## 770B 放进集群，每个 token 只走 49B

Hy4 preview 使用 MoE，也就是混合专家架构。它的主干有 78 层，后面 77 层各自放着 256 个路由专家和 1 个共享专家。一个 token 经过时，路由器会选中 8 个专家，再加上共享专家一起计算。

团队里的人很多，每个任务只叫来其中一小组。Hy4 因此可以把总参数做到 770B，每个 token 实际激活 49B。

49B 不能直接等同于一款普通的 49B 稠密模型。路由和多卡通信都有额外开销，770B 权重也得放进显存或分层存储。官方给 vLLM 和 SGLang 准备的部署示例都使用 8 路张量并行，这是一款面向服务器集群的开源旗舰。

和 Hy3 放在一起看，变化更直观。Hy3 是 295B 总参数、21B 激活参数和 256K 上下文。Hy4 的总参数大约变成 2.6 倍，激活参数约为 2.3 倍，上下文扩大到原来的 4 倍。

1M 上下文使用 Gated DSA 稀疏注意力来降低计算量。它会先从长上下文里选出 top-k 2048 个相关位置，IndexCache 再把稀疏索引拿到不同层之间复用。Hy4 还带了一层原生 MTP，通过推测解码缩短生成等待。

腾讯给 1M 上下文准备了一个很具体的任务。模型要审核 24 笔报销申请，自己判断多个版本的制度该用哪一份，还得查人员名单和发票台账，邮件里的补充信息也要处理。交付结果需要写清每一笔是通过、核减还是退回，计算过程和引用来源都不能漏。

窗口大，只说明能放进去的材料多。几十万 token 以后还能不能找回正确文件、记住前面的约束，仍然要靠真实任务验证。

## 价格涨了，权重和 API 都已上线

Hy4 preview 的官方 API 标价很具体。

每百万 token，缓存输入 0.042 美元，普通输入 0.834 美元，输出 2.501 美元。

假设一次长任务读入 100 万 token，再生成 20 万 token，不计算缓存优惠，模型费用大约是 1.33 美元。Agent 中途调用工具，继续带着历史记录往下跑，输入和输出还会继续增加。

把它和上一代 Hy3 放在一起看，变化会更直观。OpenRouter 当前给 Hy3 列出的价格是输入 0.126 美元、输出 0.522 美元。Hy4 的输入单价大约是 6.6 倍，输出大约是 4.8 倍。

能力涨了，单次 token 也明显更贵。

腾讯在 GitHub 的已知限制里主动写明，当前 preview 版处理复杂任务时会思考得比需要的更久，也有反复验证自己工作的倾向。Hy4 默认使用 high 档深度思考，简单请求可以把 `reasoning_effort` 设为 `no_think`。

多想一会儿会增加等待时间，也会增加输出 token。修一个 Bug 到底调用几轮，工具失败以后要重来几次，测试能否通过，这些数字加在一起，才是 Agent 实际花掉的钱。

普通权重和 FP8 版本已经可以下载，许可证使用 Apache 2.0。GitHub 仓库给出了 vLLM、SGLang 和微调流程，服务启动以后可以通过 OpenAI 兼容接口调用。

多数个人开发者更现实的方式，还是通过腾讯云 TokenHub、OpenRouter 或 OpenCode Go 调用 API。截至 8 月 29 日，OpenRouter 只列出腾讯云一家供应商，页面显示的早期中位吞吐大约是每秒 40 token，结构化输出错误率接近 16%。

模型刚上线，样本来自哪些应用也不透明，这几项数字随时会变。我不会拿它们给 Hy4 下结论。项目如果依赖 JSON Schema 和稳定工具参数，上线前需要重新测。

## 哪些项目值得测

项目需要处理大型代码库，或者经常让 Agent 连续工作很久，Hy4 preview 值得进入测试名单。1M 上下文和长程任务训练都对着这些场景，OpenAI 兼容接口也方便接进现有系统。

团队计划私有部署，Apache 2.0 和完整权重会很有价值。代价也很明确，服务要准备多卡环境，推理框架和模型版本都得自己维护。

接进项目以后，可以拿现有任务集跑一遍 Hy3 和 Hy4。记录每个任务用了多少轮、花了多少 token，再看测试有没有通过。长上下文单独测一次，把会互相冲突的新旧文档一起放进去，看模型能不能持续选对版本。

普通聊天、短代码生成或预算很紧的批量任务，Hy4 的调用价格未必划算。Hy3 以及更小的开源模型仍然有自己的位置。模型越大，只有在少重试几轮、少返工一次的时候，贵出来的钱才可能省回来。

我的判断很简单，Hy4 preview 已经值得进入 Agent 项目的测试名单。发布页里的 770B 很醒目，项目里只看两件事，任务能不能做完，做完一次要花多少钱。

49B 激活参数负责把它跑起来。值不值得用，要交给真实项目验证。
