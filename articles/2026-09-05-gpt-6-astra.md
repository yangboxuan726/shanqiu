大家好，我是「山丘代码铺」。

OpenAI 发布 GPT-6 Astra 时，Greg Brockman 在结尾写了一句「Welcome to the AGI era」。

欢迎来到 AGI 时代。

我把 OpenAI 的发布页、ARC Prize 的分析和这两天冒出来的实测对了一遍。说真的，我看完是兴奋的。

Astra 已经从聊天框走到了电脑前面。

它会打开网页，读文件，调用终端和软件，根据屏幕上的反馈继续往下做。中间出了错，它还得调整路线，直到交出一个能检查的结果。

三个数字最能说明这次变化。

OpenAI 公布的 OSWorld V2-Offline 成绩是 72.6%，GPT-5.6 Sol 为 65.7%。这项测试考模型能不能操作一台真实电脑，把桌面任务做完。

MarkTechPost 对公开结果的整理还提到，相关桌面任务的平均耗时从大约 75 分钟降到了 40 分钟。

单次少 35 分钟，看着只是速度变化。一天连续跑 10 个类似任务，差出来接近 6 个小时。当然，这只是把报道里的平均值做直观换算，具体项目不会整齐地快这么多。

ARC Prize 给出的最高结果是 99.9%。这个数字有重要条件，后面会单独讲。

现在先看最能落到手上的一件事。Astra 开始有机会把一整段电脑工作接过去。

## 操作电脑为什么这么难

很多朋友第一次看到 OSWorld，可能会把它理解成电脑知识考试。

这个测试直接把模型放进任务环境，考的是操作。

模型面前有浏览器、文件、窗口和各种软件。它要点按钮，输入内容，拖文件，切应用，还要处理过程中不断变化的页面。

评分也看最终状态。文件有没有放进正确位置，表格有没有填对，设置有没有真的保存，都会影响结果。模型写一段听起来很合理的说明，没有完成操作，成绩仍然是零。

单个动作通常不难。

难的是动作之间的衔接。

一批资料要整理成结果，往往要先翻网页，再下载 PDF，把字段录进表格。发现数字不对，还得回原文核对，最后写进文档。

前一步做错，后面会一路跟着歪。

人操作电脑时，很多动作靠经验顺手完成。按钮换了位置，弹出一个确认框，或者文件名和预期不同，我们看一眼就会调整。模型要把这些变化重新放回当前目标里，难度就在这里。

模型接到这类任务，通常会走过五个环节。

理解目标，采取行动，读取反馈，修正路线，验证结果。

OpenAI Developers 在发布材料里还提到异步工具调用和 mid-response steering。前者允许模型在等待某些工具返回时继续推进其他工作，不必完全阻塞在单个调用上。后者允许用户在模型工作途中补充要求，它能调整正在执行的任务，不必整段推倒重来。

这两项能力都服务于长任务。现实工作经常会遇到慢工具，也会在做到一半时收到新的限制，模型能否接住这些变化，直接影响人要不要重新接管。

早期模型常在第三步以后掉链子。它会启动，也能做出一部分结果，任务一长就容易忘掉最初要求。工具报错以后，它有时只解释错误，工作停在那里。

人只好重新接管。

Agent 最烦人的时刻通常发生在任务中段。人离开电脑一会儿，回来才发现模型在同一个错误上循环了二十分钟。

OSWorld 的成绩上涨，价值就落在这里。

它说明 Astra 在真实电脑环境里，确实更不容易在任务中途掉链子。至于能不能接住你的项目，还得看真实任务。

我看到这里，会想起电力刚进入工厂的那段历史。

最初人们只是用电动机替掉蒸汽机，真正的生产率提升，后来来自围绕电力重新设计生产流程。

Astra 也类似。把它留在聊天框里，只能用到部分能力；接上浏览器、文件系统、终端和专业软件以后，工作方式才开始改变。

## 三个案例，看它到底强在哪

先看一个很小的任务。

雪瑜在 X 上给 GPT-6 Astra Medium 和 GPT-5.6 Sol Medium 发了同一条提示词。

生成一个 SVG 动画，让鹈鹕骑自行车，再用 H5 展示。

两个模型都做出了画面，也都支持变速。Sol 里的鹈鹕腿几乎不动，脚蹬和身体没连起来。Astra 一遍完成，鹈鹕的腿、脚蹬和自行车动作更连贯，整体也更像一个交付完成的小作品。

![GPT-6 Astra 与 GPT-5.6 Sol 同一提示词生成的鹈鹕骑车 SVG 对比](assets/2026-09-05-gpt-6-astra-vs-gpt-5-6-sol-pelican-x-post.png)

*图，雪瑜在 X 上发布的同提示词对比截图*

这类对比很直观。读者不需要认识任何 Benchmark，扫一眼就知道哪个版本把需求做完整了。

工程任务更硬一些。

Paweł Huryn 公布的 Bug Hunt Bench 使用了 2 个真实代码仓库，里面放入 105 个已知 bug，再让不同模型自己找和修。

这项测试只给事先埋进去的 bug 计分。模型顺手修掉其他真实问题，会单独记录，不会加到 105 分里。

max effort 条件下，GPT-6 Astra 修好 48 个，Fable 5.1 修好 43 个，GPT-5.6 Sol 修好 42 个。

Fable 5.1 用时约 73.1 分钟，Astra 约 78.8 分钟。Fable 稍快。

成本差得更明显。Astra 约 31.21 美元，Fable 5.1 约 77.55 美元。

这组测试给出的结论很具体。Astra 多修好 5 个 bug，时间多花了几分钟，费用不到 Fable 5.1 的一半。

一项测试代表不了所有仓库，不过程序员已经能据此设计自己的复测。拿真实 issue、真实单测和真实账单说话，比一句「全面碾压」有用得多。

这里还有一个会影响结果的条件。Astra 跑在 Codex CLI，Fable 5.1 跑在 Claude Code。分数里既有模型能力，也有执行环境的作用。它很接近真实使用，却依然不能当成纯模型智商表。

再把任务拉长。

ZHO 在 X 上给 Astra 一张建筑照片，让它连续运行 8 个小时。

公开的进度里已经出现 Rhino 建筑模型、Grasshopper 帆面分格、离线空间漫游、IFC4 技术模型、14 张 A1 技术图、一套 CAD 图纸、建筑分析展板和影响预演。

![GPT-6 Astra 连续运行 8 小时完成建筑全流程任务](assets/2026-09-05-gpt-6-astra-zho-architecture-workflow-x-post-crop.png)

*图，ZHO 在 X 上公布的 Astra 建筑全流程测试进度*

这项任务还没全部结束。原帖明确写着，2 个成片和高精度模型仍未完成。

已经完成的部分仍然很夸张。模型要在多个专业软件之间移动，读取中间结果，再把模型、图纸和演示接着做下去。

一条 X 实测也不能证明建筑师已经可以被替代。图纸精度、结构安全、施工规范和最终交付仍要由专业人员检查。这个案例证明的是任务跨度，Astra 已经能把很多原本分散的步骤串起来跑。

小动画测完成度，真实仓库测修复能力，8 小时建筑任务测它能把工作推进多远。

材料到这里已经够了。

## 这些分数到底在测什么

下面的数据来自 OpenAI 官方发布。它们能说明 Astra 在厂商评测里的能力分布，不能替真实项目盖章。

两套榜单的任务、工具和推理预算不同，结论自然会分叉。现有材料足以确认 Astra 很强，尤其擅长电脑操作和长任务。全面第一还缺少统一证据。

## 99.9% 后面有一行小字

ARC-AGI-3 测试模型怎样面对陌生的互动任务。

它有点像一款没有说明书的新游戏。模型要尝试动作，观察反馈，再慢慢摸清规则。背过多少知识在这里帮不上太多。

ARC Prize 公布了两套结果。

Standard harness 得分 62.7%，成本约 2.6 万美元。

Provider Adapter harness 得分 99.9%，成本约 1.9 万美元。

harness 可以理解成模型和测试环境之间的执行程序。它决定模型能看到什么反馈，怎样提交动作，前面的对话如何保留，失败后能不能继续。

Provider Adapter 还加入了持续对话和定制的上下文压缩。模型能带着更完整的历史继续玩，也更少因为上下文塞满而丢掉早先发现的规则。

同一个 Astra，接法变了，成绩从 62.7% 跳到 99.9%。

成本出现了一个反常结果。高分版本约花 1.9 万美元，Standard harness 反而约花 2.6 万美元。ARC Prize 的分析提到，Astra 在更好的执行程序里会用更少动作完成关卡，模型调用和 token 消耗也跟着下降。

能力更强、花费更低，在 Agent 任务里可以同时发生。模型少走几次弯路，通常比便宜几美元的百万 token 单价更重要。

所以标题里的 99.9% 必须带上 Provider Adapter 这个条件。它不等于 Astra 面对所有陌生任务都有 99.9% 的成功率。

62.7% 依然是很强的结果。ARC Prize 还记录到，在特定执行设置下，Astra 在大约 96% 的关卡上超过了人类的动作效率。

这项测试也提醒了做 Agent 的团队，模型和执行系统要放在一起看。工具、反馈、上下文管理都会改变最后结果。

## 哪些任务值得交给 Astra

我会用四个条件判断。

输入分散在网页、文件、表格、日志或者代码仓库里，中间还要打开多个软件，走过很多步骤。

执行时可能出错，模型得根据反馈改变做法。任务结束以后，还要留下一个可以检查的交付物。

四项同时出现，Astra 才有机会把优势发挥出来。

复杂仓库排错、多份材料交叉核对、跨来源研究、CAD 和 3D 工作流，都符合这个形状。

拿文档和研究任务来说，可以让 Astra 读完几十份文件，统一同名指标的口径，找出数字冲突，再回到原文核对，最后整理成带出处的表格。

代码任务也一样。让模型写一个函数很短，让它进入真实项目，重现故障，沿着日志找到调用位置，改完再跑测试，才会用到 Astra 擅长的那部分能力。

桌面自动化还有一类很常见的活。浏览器里下载数据，放进本地表格，清理格式，再把结果更新到后台系统。过去需要人不断复制、粘贴和确认，Astra 可以尝试把这些步骤连起来。

这类任务有一个共同点，人自己做得出来，只是中间步骤又多又碎。Astra 的价值会直接落在节省的时间和减少的人工接管上。

普通问答、短邮件、一次性摘要和几行代码，轻量模型已经够用。Astra 的调用价格高，短任务也发挥不出长时间执行的优势。

真正上线前，最好拿自己现有的任务集跑一遍。记录完成率、耗时、费用和人工接管次数，再决定要不要替换当前模型。

## 贵不贵，要按完整任务算

GPT-6 Astra 的 API 价格是每百万输入 token 10 美元，每百万输出 token 50 美元，和 Fable 5.1 相同。

它提供 105 万 token 上下文窗口，最大输出 12.8 万 token。

这个价格很高。

一次调用多少钱，解释不了 Agent 的真实成本。完整任务还会产生多轮推理、工具调用、失败重试和人工接管。

105 万 token 的上下文会产生真实费用。资料放得越多，读取和推理越贵。只把当前任务需要的文件交给模型，再用缓存和检索减少重复内容，账单会更容易控制。

可以算一笔很简单的账。一次任务如果产生 10 万输入 token 和 1 万输出 token，模型费用大约是 1.5 美元。Agent 连续运行十几轮以后，历史对话、工具定义和文件内容会反复进入上下文，实际费用很快就会高于这次单轮计算。

所以大上下文解决的是能不能装下，缓存和任务拆分决定最终花多少钱。

Bug Hunt Bench 里，Astra 和 Fable 5.1 的标价相同，Astra 的实际费用却低很多。原因很直接，它用更少的 token 完成了更多修复。

换到别的任务，结果可能反过来。团队要算的是一项工作最终花了多少钱，交付物有没有通过验收。

截至写稿，Astra 已经在 ChatGPT Work、Codex 和 API 上线，并向 Plus、Pro、Business 和 Enterprise 用户推送。不同订阅档位的额度并不相同，长任务仍然要留意使用上限。

## 能力过线，权限也要收紧

OpenAI 的安全概览把 GPT-6 Astra 列为首个达到 Preparedness Framework 网络安全 Critical 级的模型。

按 OpenAI 的描述，它能在缺少人类逐步指导的情况下发现未知漏洞，并继续发展利用方式。

这个能力可以帮助安全团队审查系统，也会降低攻击者的门槛。

The Decoder 根据 OpenAI 系统卡和 Gray Swan 的独立测试整理过一组数据。直接提示词注入的防御率约为 99.99%，攻击者改成多轮自适应尝试以后，防御率降到约 67%。

静态攻击和长时间对抗，难度差很多。模型在电脑上工作越久，接触的网页、文件和工具越多，隐藏指令混进任务的机会也会增加。

模型开始自己操作电脑以后，权限控制会直接影响后果。它调用过哪些工具，改过哪些文件，为什么改变计划，都得留下记录。

生产环境需要沙箱，高风险操作需要人工确认，任务跑偏以后还要能立刻停掉。

能力涨上去，外面的控制系统也要跟上。

## 写在最后

OpenAI 用「Welcome to the AGI era」结束了这次发布。

看完这句话和这些实测，我越来越期待 AGI 时代真正到来。

眼前的变化已经足够具体。模型开始操作电脑，能在多个软件之间连续工作，还能根据反馈继续修正。

我看完这些测试会兴奋，原因也在这里。

**以前的大模型帮你完成一个动作。**

**Astra 开始有机会接住一整段工作。**
